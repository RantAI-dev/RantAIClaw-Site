# Setup Wizard

`rantaiclaw setup` is the recommended way to configure an agent for the first time. It writes the active profile's `config.toml`, drops credentials into encrypted `enc2:` inline values, and provisions the `policy/`, `persona/`, and `skills/` directories under `~/.rantaiclaw/profiles/<active>/`.

`rantaiclaw onboard` is an alias kept for backward compatibility with earlier releases.

For a step-by-step walk-through, see [Your First Agent](/docs/getting-started/first-agent).

## The seven sections

`rantaiclaw setup` (or `/setup` inside the TUI) walks a picker over the configurable subsystems. Each is independently re-runnable; pick the named section to jump straight in.

| Section | When to use it | What it writes |
|---|---|---|
| **provider** | First-time or switching LLM provider | `default_provider`, `default_model`, encrypted `api_key` in `config.toml` |
| **approvals** | Tightening or loosening autonomy | `policy/autonomy.toml` (L1-L4 preset), `policy/command_allowlist.toml`, `policy/forbidden_paths.toml` |
| **channels** | Adding Telegram / Discord / Slack / WhatsApp / etc. | `[channels_config.<name>]` block per channel + encrypted bot tokens |
| **persona** | Picking the agent's tone/role | `persona/SYSTEM.md` with templated content |
| **skills** | Bundled starter pack + ClawHub discovery | Skills in `skills/<name>/SKILL.md` + `[skills.entries.<name>]` config |
| **mcp** | Picking curated MCP servers (Filesystem, Web Fetch, Time, Notion, Slack, GitHub, Google Drive) | `[mcp_servers.<name>]` blocks + OAuth tokens in `secrets/` |
| **memory** | Choosing memory backend | `[memory]` block (sqlite / lucid / postgres / markdown / none) |

A "Hardware" section is gated by the `hardware` feature flag and only appears when built with hardware support.

## Re-running setup

Setup is idempotent — re-running it lets you change providers, swap personas, add channels, refresh credentials, and add or modify MCP servers without losing existing data.

```bash
rantaiclaw setup              # interactive top-level picker
rantaiclaw setup mcp          # jump into the MCP section
rantaiclaw setup approvals    # jump into approvals
rantaiclaw setup hardware     # hardware peripherals (feature-gated)
```

Inside the TUI, `/setup <section>` does the same in-process — no need to leave the chat.

## Hot-reload on close

When you Esc the setup overlay (or finish a wizard), three things happen automatically:

1. The new `config.toml` is written (with secrets encrypted to `enc2:<hex>` inline).
2. The **config watcher** (v0.6.37+) detects the file change and triggers `reload_config`.
3. The agent rebuilds via `Agent::from_config`, picking up the new provider / persona / channels / MCP servers / memory backend — and emits a `⟳ config.toml changed — agent reloaded; next turn uses the new settings.` system message in scrollback.

You don't need to restart the process. Exceptions:

- **New channel listeners** still need a restart (the daemon's `start_channels` task spawns at boot only; auto-spawn after wizard close is a v0.6.8 deliverable). The wizard tells you this with a `⚠ N new channel(s) configured. Restart rantaiclaw to start polling them.` system message.
- **Sandbox / feature-gated backends** (Bubblewrap, Postgres memory, Matrix channel, etc.) need a rebuild with `--features <name>`.

## Non-interactive setup

For automation (CI, Docker entrypoints), pass `--non-interactive` and provide values via env vars or flags:

```bash
RANTAICLAW_PROVIDER=openrouter \
RANTAICLAW_API_KEY=$OPENROUTER_KEY \
RANTAICLAW_MODEL=anthropic/claude-sonnet-4.6 \
rantaiclaw setup --non-interactive
```

Recognized env vars consumed by the non-interactive path:

| Env var | Effect |
|---|---|
| `RANTAICLAW_PROVIDER` | Default provider |
| `RANTAICLAW_API_KEY` | Provider API key |
| `RANTAICLAW_MODEL` | Default model name |
| `RANTAICLAW_PROFILE` | Profile to provision (defaults to `default`) |
| `RANTAICLAW_CONFIG_DIR` | Override config directory |
| `RANTAICLAW_WORKSPACE` | Override workspace directory |

Note: env vars like `RANTAICLAW_AUTONOMY` and `RANTAICLAW_CHANNELS` are **not** recognized today — channel and autonomy choices are interactive-only or driven by the config file you preload. For full automation, drop a pre-built `config.toml` into the profile directory before invoking the daemon.

## Selecting a profile

To set up a specific profile (instead of `default`):

```bash
rantaiclaw --profile work setup
```

Or via env:

```bash
RANTAICLAW_PROFILE=work rantaiclaw setup
```

See [Profiles](/docs/concepts/profiles) for the full profile model.

> **Status note:** the CLI surface is alpha. Flag names and env var names may change before 1.0. Pin to a known release for production use.
