# Troubleshooting

> **v1 status:** seeded with the most common failures from `rantaiclaw doctor` and the codebase's known sharp edges. The canonical reference in the upstream repo is [`docs/troubleshooting.md`](https://github.com/RantAI-dev/RantAIClaw/blob/main/docs/troubleshooting.md).

## Install / first run

**`rantaiclaw: command not found`**
The installer placed the binary in `~/.cargo/bin` or `~/.local/bin`, neither of which is on your `PATH`. Re-run the bootstrap and copy the `export PATH=...` line it prints into your shell rc.

**`failed to verify checksum`**
The download was corrupted or tampered with mid-flight. Re-run the bootstrap; if it persists, file an issue with your platform info.

## Provider

**`provider api_key invalid`**
Your credential was revoked or never set. Run `rantaiclaw setup`, pick the same provider, the wizard overwrites the secret in the encrypted inline `enc2:<hex>` value.

**`provider rate_limited` / 429**
Transient. The `ReliableProvider` wrapper retries with exponential backoff (capped at 10s) and rotates through `[reliability].api_keys` if you've supplied multiple. If it persists, switch to a higher-tier API key, configure a fallback provider, or add per-model fallback chains.

**`context window exceeded`**
The retry wrapper recognizes this as non-retryable and surfaces it. Trim the context (shorter system prompt, smaller `K` for memory recall) or move to a model with a larger context window.

## Channels

**`channel <name> offline / not responding`**
Most likely the bot token is wrong, the bot was kicked from its allowlisted chat, or the network is unreachable. Verify the bot in the platform's UI, then re-run `rantaiclaw doctor`.

**`channel <name> empty allowlist`**
You enabled the channel but did not add anyone to its allowlist. Most channels treat empty allowlist as offline (deny-by-default). Check the right config key — see [Reference → Channels](/docs/reference/channels) for the per-channel allowlist key names (`allowed_users` / `allowed_contacts` / `allowed_from` / `allowed_numbers` / `allowed_senders`).

**Email replies to everyone, not just my allowlist**
Email is the one channel that allows-all on empty `allowed_senders`. Set explicit allowed senders or domain prefixes (`@example.com`) to restrict it.

## Gateway

**`Refusing to bind to 0.0.0.0 — set [gateway].allow_public_bind = true`**
Exactly what it says. Add `allow_public_bind = true` to `[gateway]`, or change `host` back to `127.0.0.1`. Alternative: set `RANTAICLAW_ALLOW_PUBLIC_BIND=1` in env.

**`webhook signature mismatch`**
Either the HMAC secret is wrong, or the request was tampered with mid-flight. Verify the secret matches the upstream service's webhook configuration. Note: only the channel-specific endpoints (`/whatsapp`, `/linq`, `/nextcloud-talk`) verify HMAC over the body. The generic `/webhook` endpoint uses an `X-Webhook-Secret` shared secret check, not body HMAC.

**Pairing token rejected**
Tokens are stored as SHA-256 hashes — you cannot recover them from `[gateway].paired_tokens`. Pair again via `POST /pair` with `X-Pairing-Code` to issue a fresh token.

## Approval / Autonomy

**Tool call hits `Command not allowed by security policy: brew --version`**
The shell command's basename isn't on the static allowlist. As of v0.6.5, this triggers the async approval flow — the agent emits a system message and waits for `/allow brew`, `/allow brew --persist`, or `/deny brew`. On chat channels, reply with `allow brew` (or `y brew` / `Y brew` for short forms). 5-minute auto-deny timeout.

If you don't see the approval prompt, you might be on a pre-v0.6.5 build — upgrade. If you're on Full autonomy mode, the allowlist is bypassed entirely; that's by design.

**`rantaiclaw chat` hangs after a tool call**
The legacy CLI approval prompt blocks on `stdin.read_line` with no timeout — `timeout_secs` is written to the policy file but no consumer reads it yet. Type `y` or `n`. If you've launched the agent in a non-interactive context where stdin isn't connected, add the tool to `auto_approve` instead, or use the TUI (`/allow brew`).

**Agent exits with `[no response from model — try /retry or rephrase]`**
The provider returned empty final text. Common causes:
- Hit `agent.max_tool_iterations` (default 10) — the agent now emits a forced summary instead of going silent (v0.6.5+). If you see the silent variant, you're on an older build.
- Provider 401/403 — check the api_key in config. Try `RANTAICLAW_PROVIDER=…` env override to bypass stored credential.
- Provider returned a tool call but no text. The retry path triggers a tools-disabled summary call.

**Agent is stuck repeating the same tool call**
The loop detector (v0.6.5+) breaks out after 3 identical `(tool, args, result)` triples within a 5-call window. If you're seeing this, the loop detector is doing its job. Type `/calls` to see what got tried.

**`/continue` re-runs the same failed work**
By design — `/continue` resubmits the current conversation with a fresh `max_tool_iterations` budget. If you want to steer the next iteration, type `/continue install missing deps` instead (the trailing text becomes additional guidance).

## MCP

**`mcp server <name> launcher not on PATH`**
`rantaiclaw doctor`'s MCP check only verifies the launcher binary (`npx`, `node`, etc.) is on `PATH`. Install it, then re-run `doctor`.

**`/mcp` shows my server as ✗ with "failed to discover"**
The agent's MCP discovery (v0.6.35+) ran at boot, attempted `initialize` + `tools/list`, and failed. Common causes:
- Wrong npm package name in `[mcp_servers.<name>].args` — for example `@modelcontextprotocol/server-time` doesn't exist on npm; use `uvx mcp-server-time` instead.
- `uvx` not on PATH — Python MCP servers need [`uv`](https://docs.astral.sh/uv/) installed. Run `curl -LsSf https://astral.sh/uv/install.sh | sh`.
- Server crashed during init — run `<command> <args>` manually outside RantAIClaw to see the actual error.

**Adding to `[mcp_servers.foo]` in config.toml doesn't immediately work**
As of v0.6.37 the config watcher fires on direct edits and reloads the agent with a `⟳ config.toml changed — agent reloaded` system message. If you don't see that line within ~2 seconds of saving, the watcher may not be active — check rantaiclaw logs for `config watcher disabled`. Workaround: `/quit` and relaunch.

**MCP tool name doesn't match what I expected**
Tool names are namespaced `mcp__<server>__<tool>`. Special chars (`.`, `-`) are sanitized to `_`. So a server `my-server` exposing a tool `do.thing` becomes `mcp__my_server__do_thing`. Match Claude Code's convention so users coming from there have one less surprise.

**`rantaiclaw setup mcp` offered Google Calendar / Gmail but they failed to install**
Removed from the curated list as of v0.6.38 — no official MCP server exists in the [reference registry](https://github.com/modelcontextprotocol/servers) for either. If you see those options, you're on an older build.

## Sandbox

**`landlock unsupported on this kernel`**
Landlock requires Linux ≥ 5.13. Either upgrade the kernel or accept the warning — RantAIClaw's sandbox auto-detection falls through to the next available backend (Firejail → Bubblewrap → Docker → Noop).

**`sandbox-bubblewrap requires --features sandbox-bubblewrap`**
Bubblewrap is feature-gated at build time. Rebuild with `cargo build --release --features sandbox-bubblewrap`, or pick a different backend in `[security.sandbox]`.

## Memory

**`memory backend postgres requires --features memory-postgres`**
You configured `[memory] backend = "postgres"` with a binary built without the feature. Rebuild with `cargo build --release --features memory-postgres`, or use the `sqlite` / `lucid` backend instead.

**Recall returns nothing useful**
The default embedding provider is `none` — recall is purely lexical (BM25) until you configure a real embedding provider:

```toml
[memory.embedding]
provider = "openai"
model = "text-embedding-3-small"
```

Plus an API key in env or in the appropriate provider block.

**`brain.db` missing after a redeploy**
If you enabled `[memory] snapshot_enabled = true`, Core memories are auto-hydrated from `MEMORY_SNAPSHOT.md` on cold boot. Otherwise the agent starts fresh. Mount the workspace volume between deploys to preserve memory.

## Profile / paths

**Where is my config?**
Default: `~/.rantaiclaw/profiles/default/config.toml`. Override with `--profile <name>`, `RANTAICLAW_PROFILE=<name>`, or `RANTAICLAW_CONFIG_DIR=<path>`. Same path shape on Linux, macOS, and Windows.

**`active_profile` says one thing but `--profile` flag overrides it — which wins?**
The `--profile` flag wins. Resolution order: `--profile` → `RANTAICLAW_PROFILE` → `~/.rantaiclaw/active_profile` → `default`.

**`config.runtime.toml` doesn't seem to take effect**
Correct — the loader exists in `src/config/runtime.rs` but is not currently called from `Config::load_or_init`. Live overrides via that file are planned but not yet wired. Edit `config.toml` directly.

**Edited `default_model` in config.toml but rantaiclaw still uses the old one**
Env vars override config. If `RANTAICLAW_MODEL` is set (often in `.env` or your shell rc), it wins over the config file. Check your env: `env | grep RANTAICLAW`. The precedence is: CLI flag > env var > config file > default.

## Streaming / cancellation

**`esc to interrupt` cancelled but my bill kept growing**
RantAIClaw's cancellation only stops the local future — the upstream provider keeps generating tokens for the remaining ~1-3 seconds (longer for some providers). You're billed for those tokens. This is a known trade-off — no LLM provider currently exposes a "cancel in-flight" API. Documented on every supported provider in [Providers](/docs/reference/providers).

**Anthropic / OpenAI / Gemini streaming returns nothing or errors**
As of v0.6.39 these three providers route through `rig-core` instead of hand-rolled HTTP. If something is misbehaving:
1. Try the legacy fallback: rebuild with `cargo build --release --features legacy-providers` to route back through the pre-v0.6.39 hand-rolled implementations.
2. File an issue with the exact provider + model + first 200 bytes of the error.
3. The legacy path will be removed in v0.7.0 after one release cycle of clean rig usage.

**`/mcp` shows tools but the agent says they're not available**
The agent only sees tools that were registered at its boot or via hot-reload. If you added a server via direct config-edit but the agent was already mid-turn, the new tools land at the next agent turn (which fires `Agent::from_config` rebuild). Send a new message and try again.

## Hot-reload

**Edited config.toml but no `⟳ config.toml changed` system message appeared**
The config watcher (v0.6.37+) uses notify with a 500 ms debounce. If you're using an editor with atomic writes (vim, vscode default), the rename should be picked up. If not:
1. Check rantaiclaw stderr/logs for `config watcher disabled: <reason>` at startup.
2. Try `touch config.toml` after your edit to force a Modify event.
3. Restart rantaiclaw as a fallback — the new config loads at boot regardless.

**Hot-reload fired but the change didn't take effect**
Some config keys require restart even with hot-reload:
- Channel listener tasks (adding `[channels_config.discord]` reloads config but doesn't auto-spawn the listener — restart needed; deferred to v0.6.8)
- Sandbox backend (Cargo-feature gated; needs rebuild)
- Memory backend swap (e.g. sqlite → postgres requires `--features memory-postgres` build)

The `⚠ N new channel(s) configured. Restart rantaiclaw...` system message tells you when restart is required.
